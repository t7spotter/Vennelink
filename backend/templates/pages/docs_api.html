API reference

v1

A small REST API over everything the dashboard can do. Every endpoint needs an API key; every response is JSON.

Base URL

All endpoints below are relative to this installation:

{{ SITE_URL }}/api/v1/…

Get an API key

Exchange your username and password for a key. The response is the only time the key is readable — store it somewhere safe. It can be re-issued by calling again, and revoked with an authenticated DELETE (or from the profile page). 

curl -X POST {{ SITE_URL }}/api/v1/token/ \
  -H "Content-Type: application/json" \
  -d '{"username": "you", "password": "••••••"}'

# → 201
# {"token": "9944b09199c62bcf9418ad846dd0e4bbdfc6ee4b"}

Authentication

Send the key on every request. Both header spellings are accepted: 

Authorization: Bearer <api key>
Authorization: Token <api key>

Endpoints

Links are looked up by short code, and every query is scoped to the key's owner — deleting a link removes its click history with it.

Method Path What it does
GET /api/v1/me/ Your profile.
GET /api/v1/links/ List your links. Paginated with ?page=.
POST /api/v1/links/ Create a short link.
GET /api/v1/links/{code}/ Retrieve one link by short code.
PATCH /api/v1/links/{code}/ Partially update a link.
DELETE /api/v1/links/{code}/ Delete it — click history goes with it.
POST /api/v1/links/{code}/activate/ Start redirecting again.
POST /api/v1/links/{code}/deactivate/ Stop redirecting.
GET /api/v1/links/{code}/analytics/ Per-link analytics. Bots excluded unless ?bots=1.
GET /api/v1/stats/ Dashboard totals for the current user.

Create a link

curl -X POST {{ SITE_URL }}/api/v1/links/ \
  -H "Authorization: Bearer $VENNELINK_KEY" \
  -H "Content-Type: application/json" \
  -d '{"destination": "https://example.com/article", "title": "Article"}'

# → 201
# {"code": "k3mQx9", "short_url": "{{ SITE_URL }}/k3mQx9", …}
